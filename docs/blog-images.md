# ブログ画像の作り方

ブログ記事に使う画像の作り方と、使い分けをまとめます。ブログ作成の流れ（ネタ帳 → レポート → 本文 → 画像 → チェック → WordPress）は [blog-brief.md](blog-brief.md) と `tasks/CURRENT.md` を参照してください。

最終更新: 2026-11-06

## これまでの手動運用（ユーザーが行っている方法）

- ChatGPT のチャット「美容室ビフォーアフター」（ChatGPT のピン留め。ほかに「ブログ更新」「ヘアトレンド連載」「SNS・SEOネタ」などのチャットあり）で、記事の HTML や画像の指示（例: 画像①記事冒頭／画像②施術の種類の違い／画像③施術例）を渡し、写真風の画像を作る。
- 同じ記事の中では、同じお客様・同じ服装になるように指示する。スタッフはなるべく写さない。
- 作った画像を手元で `.webp` に変換して、WordPress の記事に載せる。
- 例: 投稿 6304「髪質改善トリートメントとは？縮毛矯正との違いを美容師が分かりやすく解説」（2026-11-06 公開）。

### このチャットで固定している作り方（2026-06〜11 のやり取りから要約）

ChatGPT 側には専用の「スキル」が保存されているわけではなく、同じチャットの中で積み重ねた指示（下記）と、ユーザーが貼った参考写真が「固定の仕様」になっている。Codex はこのチャットを読めないため、Codex で同じことをするには、下の仕様と参考写真をこちらで渡す。

1. **参考写真から作る**: サロンで撮ったビフォーアフター写真や店内写真を貼り、「人物のみを変えて新たに作る」。
2. **背景固定・人物のみ変更**: 椅子・床・壁・棚・テーブル・鏡・機材・店内の雰囲気・構図はできるだけ元の写真のまま。変えるのは人物・服装・髪型・髪の状態だけ。店内写真（2026-09 時点で7枚）を背景・構図の参考として使う。
3. **ビフォーアフターの見せ方**: 左右に Before／After を並べ、上に小さな Before・After のラベル。After は「別人のようにツルツル」にせず、毛流れが整いツヤとまとまりが戻った自然な状態にする。
4. **髪の状態の描き分け**: ビビリ毛は、細かいチリつき・毛先のジリジリ感・表面の毛羽立ち・ツヤのない荒れた質感をはっきり出す（ただのクセ毛・広がりにしない）。白髪ぼかしカラー、縮毛矯正、髪質改善なども同じように、施術の違いが分かるように描く。ビフォーの傷みは控えめになりがちなので、強めに指示する。
5. **お客様の設定**: 主に40代・50代の女性。同じ記事の画像ではお客様と服装を同じにする。季節に合わせて服装を変える（例: 夏は袖なし・薄手）。
6. **スタッフはなるべく写さない**。
7. **記事の HTML を渡して、画像①〜③の場所と内容を指定**して作る。図解風（見出し文字入りのバナー）を作ることもあり、そのときは「エフメイクスオリジナル風」（ベージュ系・明朝体・落ち着いた雰囲気）。

## Codex 連携で作る画像（2026-11-06 から）

- アイキャッチ（1200×630）と、記事内の図解（チェック表・メモ表など）は Codex が SVG で作り、`make-images.mjs`（sharp）で PNG にする（SVG の図案には写実的な人物を描かない）。
- 人物の写真風画像も記事に使う（2026-11-06 ユーザー判断）。作り方: Codex が本文と一緒に、内蔵の画像生成（`image_gen` ツール／`imagegen` スキル。ChatGPT の画像生成と同じ仕組みで、API キーは不要）で写真風画像を作る。指示には、入れる場所・内容・同じ記事ではお客様と服装をそろえる・スタッフはなるべく写さない、を書く。生成した画像は `runtime-data/blog-drafts/<記事名>/` にコピーし、sharp で `.webp` に変換して本文に入れる。ユーザーは本文と一緒に画像を確認する。
  - 保存には `--write` が必要（読み取り専用では保存できない）。生成画像はまず `$CODEX_HOME/generated_images/` に置かれる。
  - サイズや形式は直接指定できないため、変換のときに sharp で切り抜き・縮小する。
  - 2026-11-06 に試作1枚で確認済み（runtime-data/blog-drafts/image-test/）: 生成は 1672×941 の PNG（約2.1MB）。sharp で 1200×675 の webp（約71KB）に変換して使える。指示どおり写真風・スタッフなし・文字なしになった。指示した「毛先の広がり」は控えめにしか出ないため、強調したいときは指示で強めに書く。
- 置き場所: `runtime-data/blog-drafts/<記事名>/`（Git 管理外）。
- このテーマは記事ページにアイキャッチを表示しないため、本文先頭にアイキャッチの div を入れる。
- 例: 投稿 6318「髪の履歴」、6324「冬の広がり」。

## 使い分けと注意

| 画像 | 作り方 |
| --- | --- |
| アイキャッチ・図解・チェック表 | Codex（SVG → PNG） |
| 雰囲気・髪の状態のイメージ写真 | ChatGPT の画像生成（これまでどおり）→ `.webp` |
| 実際の施術例・ビフォーアフター | サロンで撮った実際のお客様の写真（掲載の許可を得たもの） |

- AI で作った人物の写真を、実際のお客様の施術例・ビフォーアフターとして載せない。お客様が「この仕上がりになる」と受け取ると、誤解を招く表示になるおそれがある（ブログ作成の禁止事項「実在しない口コミ・施術例・Before/After」と同じ考え方）。
- AI で作ったイメージ写真を使うときは、画像の近くに「※画像はイメージです」と書き、alt に「施術事例」「ビフォーアフター」と書かない。
- `.webp` に変換するとファイルが小さくなり、表示が速くなる。Codex で作る PNG も、必要なら同じように `.webp` にしてよい（sharp で変換できる）。
- 2026-11-06 時点で、投稿 6304 の画像②・③は AI 生成の Before/After で、③の alt が「施術事例」になっている。2026-11-06 ユーザー判断で直さない（そのまま掲載）。直す作業はホームページ部署の担当。6304 は画像③（メディア 6329）がアイキャッチ＝SNS の共有画像にもなっている。6299 のアイキャッチ（メディア 6303、本文中のアフター写真）も AI 生成か未確認。直すときはアイキャッチもあわせて見直す。

## Codex に渡す参考写真の置き場所

- `runtime-data/blog-image-refs/salon/`: 店内の写真（セット面・椅子・鏡・棚など。人が写っていないもの）。背景・構図の参考にする。
- `runtime-data/blog-image-refs/before-after/`: 実際のビフォーアフター写真（施術の種類が分かるファイル名にする。例: `bibiri-01.jpg`）。髪の変化の参考にし、人物は必ず別人に変える。
- どちらも Git 管理外（`runtime-data/`）。お客様が写った写真は Git・文書・チャットに残さない。写真は生成のときに OpenAI に送られる（ChatGPT で作っていたときと同じ）。
- 2026-11-06 試作2（参考写真あり）: ユーザー承認のうえ、店内写真1枚（salon/16_39_09-4）と手本2枚を Codex の image_gen に画像として渡し、冬の広がりの Before／After を作成（1448×1086 → webp 1200×900・約154KB）。鏡・木の棚・ミント色のかご・グレーの椅子・扇風機など店内がほぼ再現され、ChatGPT と同じ見せ方になった。背景は元写真と画素単位で同じではなく、構図は少し変わる。参考写真を送るときは、送る写真を指示に書き、ユーザーの承認を得る（Codex は「外部に送らない」条件があると止まる）。
