# ブログ作成の運用

ダッシュボードのデータと Codex を使ってブログ記事を作り、WordPress に公開するまでの流れです。画像の作り方は [blog-images.md](blog-images.md)、ネタ帳の書き出しは [blog-brief.md](blog-brief.md) を参照してください。

最終更新: 2026-11-06（1本目 6318・2本目 6324 で確認した流れ）

## 担当

| 担当 | 役割 |
| --- | --- |
| ユーザー | テーマを選ぶ、参考写真を送る許可、下書きの確認、公開の判断 |
| トレンド・SEO（Claude） | ネタ帳・レポート、Codex への指示、文章・画像・リンクのチェック、公開後の確認と効果測定 |
| Codex | 本文・WordPress 用 HTML・SEO 情報・図解・写真風画像の作成 |
| ホームページ部署 | WordPress への下書き登録と公開（ユーザー承認のうえ） |

費用: Gemini・Apify は無料枠のまま。執筆と画像は Codex（ChatGPT の契約内）と Claude で行う。

## 1本の流れ

1. **ネタ集め（Claude）**: `npm.cmd run blog:brief` でネタ帳を書き出し、Codex がトレンド・市場レポートとテーマ候補を作る。Search Console・公開サイトの既存記事と重ならないか確認する。
2. **テーマを選ぶ（ユーザー）**: 新規か書き直しかも決める。
3. **本文と画像（Codex）**: `runtime-data/blog-drafts/<記事名>/` に、本文（article.md）、WordPress 用 HTML（先頭アイキャッチ・末尾の計測付き LINE ボタン入り）、meta.json、図解・アイキャッチ、写真風の画像（必要なら）を作る。参考写真を使うときは、送る写真を示してユーザーの承認を得る。
4. **チェック（Claude）**: 禁止表現（効果の保証・断定・医療的表現など）、既存記事との重なり、内部リンク（すべて開くか）、LINE ボタンが既存と同じか、画像を確認し、webp に変換する。
5. **確認（ユーザー）**: 本文と画像をまとめて見て、直したい点を伝える。
6. **下書き登録（ホームページ部署）**: ユーザー承認後に依頼文（wordpress-request.md）を送る。登録後、ユーザーがプレビューを確認する。
7. **公開（ホームページ部署）**: ユーザーの「公開する」で依頼する。
8. **公開後の確認（Claude）**: ページが開くか、H1・index・canonical・og:image・画像・LINE ボタン（line_click・article_end）・リンクを確かめ、`tasks/CURRENT.md` に記録する。

## 定期的に行うこと

- 毎週火曜: SNS の取り込み（自動、Windows タスク）。
- 月1回（月初め）: 前月の Search Console・GA4 を見て、公開した記事の表示回数・クリック・LINE クリックを確認し、書き直す記事と次のテーマを決める。
- 本数の目安: 週1本（月4本、2026-11-06 ユーザー決定）。季節の話題は1〜2か月前に公開する。新規と書き直しを組み合わせてよい。

## 決まっていること

- 写真風の画像は「背景固定・人物のみ変更」で作る。投稿 6304 の AI Before/After はユーザー判断でそのまま（2026-11-06）。
- 公開・削除・設定変更は、すべてユーザーの承認のあとで行う。
