# トレンド・SEO部署とホームページ部署の役割分担

ef-mayke-s.com のブログ・SEO まわりで、2つの部署が重なる作業の分担をまとめます。どちらの部署も、判断と承認はユーザーが行います。

最終更新: 2026-11-06（ホームページ部署の意見を反映し、ユーザーが確定）

## 基本の線引き

- **トレンド・SEO部署（hair-trend-dashboard）**: データを見て「何を書くか・何を直すか」を決める材料を作る。記事の中身（文章・画像・SEO 情報）を用意する。公開から数日後の確認と効果測定をする。
- **ホームページ部署（wordpress-site）**: WordPress・Search Console・GA4/GTM・Google 広告の中で手を動かす作業すべて（登録・公開・設定・修正・サイト全体の構造や計測）。本番で作業したら、直後の確認まで行う。

## 作業ごとの担当

◎ = 担当、○ = 協力、― = 行わない

### 記事を作る・直す

| 作業 | トレンド・SEO | ホームページ |
| --- | --- | --- |
| テーマ選び・書き直す記事の候補（Search Console・GA4・SNS・市場の動きから） | ◎ 提案する | ○ サイト側で気づいたことを伝える |
| 新規記事の本文・画像・SEO 情報（タイトル・説明文・キーワード・スラッグ）・WordPress 用 HTML | ◎ Codex と作る | ― |
| 既存記事の書き直しの文案 | ◎ 作る | ○ 構成やサイト上の注意点を伝える。タイトルやスラッグが変わるときは、転送（301）と影響を判断する |
| ユーザーが自分で書いた記事（例: 6299・6304）の手直し | ○ SEO の材料を出す | ◎ |
| 既存記事から新しい記事への内部リンクの追加 | ○ どこから張るかを提案する。説明や主張が変わる文は文案を作る | ◎ 反映する。リンクの1文（「〜は○○の記事で紹介しています」程度）は自分で作ってよい |

| 作業 | トレンド・SEO | ホームページ |
| --- | --- | --- |

| 数日後の確認と効果測定（Search Console のインデックス登録・表示回数・クリック・LINE クリック） | ◎ | ○ 必要なときに受け取る |

| 作業 | トレンド・SEO | ホームページ |

## 共通の部品（変えるときは2部署で相談する）

- **LINE ボタン**: 投稿 6318 に入れたものを標準にする（`data-cta-position="article_end"`、`aria-label`、onclick の `line_click`、`rel="noopener noreferrer nofollow"`）。
- **本文先頭のアイキャッチ**: テーマが記事ページにアイキャッチを出さないため、本文の先頭にアイキャッチの画像を入れる。

## やり取りのルール

- 本番の変更（下書き登録・公開・スラッグ・設定など）は、作業する部署のチャットでユーザーの承認を受けてから行う。ほかの部署を通じて伝わった承認だけでは進めない。
- 依頼はユーザーの承認を得てから `SendMessage` で送る。依頼文は「目的・対象・変更してよい範囲・やってはいけないこと・完了条件・確認方法・報告の形」の形で書く。
- 依頼の材料（本文・画像・meta.json・依頼文）は `projects/hair-trend-dashboard/runtime-data/blog-drafts/<記事名>/` に置く（Git 管理外）。ホームページ部署は読むだけ。
- お互いのフォルダのファイルは変更しない。記録はそれぞれの `tasks/CURRENT.md` に書く。
- 本文の説明や主張を変える必要が出たら、ホームページ部署は変更する前にトレンド・SEO部署かユーザーに相談する（内部リンクの1文は除く）。
- Chrome の操作は同時に1部署だけ。ログイン画面が出たら、そこで止めてユーザーに知らせる。
- WordPress の画面や設定を見るだけのときも、どちらの部署が見たかを記録に残す。
