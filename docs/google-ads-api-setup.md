# Google 広告の自動取り込み: Google 側の準備

Google 広告の実績（費用・表示・クリック・コンバージョン）を、CSV を手で取り込まずにダッシュボードへ自動で入れるための準備です。ユーザーが Google の画面で行います。秘密の値（鍵やパスワード）はチャットや文書に書かないでください。

最終更新: 2026-11-06

## 方針

- 認証には、GA4・Search Console の取得で使っている**既存のサービスアカウント**を使う（新しい鍵やリフレッシュトークンを作らない）。
- Developer Token は 2026-09-09 に廃止されたため不要（[Google 公式](https://developers.google.com/google-ads/api/docs/api-policy/developer-token)）。
- 権限は「閲覧のみ」。広告の出稿・停止・予算変更はしない。

## 手順（ユーザー）

### 1. サービスアカウントのメールアドレスを確かめる

GA4 の「管理 > プロパティのアクセス管理」に、`…@….iam.gserviceaccount.com` で終わるアドレスがあります。それが GA4 取得に使っているサービスアカウントです（Vercel の環境変数 `GOOGLE_SERVICE_ACCOUNT_EMAIL` と同じもの）。

### 2. Google 広告にユーザーとして追加する

1. Google 広告に管理者でログインする。
2. 「管理者 > アクセスとセキュリティ」を開き、「ユーザー」タブの「＋」を押す。
3. 1 のメールアドレスを入れ、アクセスレベルは **閲覧のみ（Read only）** を選んで招待する。
   - サービスアカウントは「メールのみ」は選べません。
   - 招待が「保留中」のまま残ることがあります。その場合は1〜2日待ちます。

### 3. Google Cloud で Google Ads API を有効にし、Explorer アクセスを申請する

1. Google Cloud コンソールで、そのサービスアカウントがあるプロジェクトを開く（GA4 Data API を有効にしたプロジェクト）。
2. 「API とサービス > ライブラリ」で **Google Ads API** を有効にする。
3. Google Ads API の「概要」ページから **Explorer アクセス**を申請する（多くは自動で審査されます）。
   - 有効にしただけでは「テスト用アカウント」にしか使えず、実際の広告アカウントは読めません。
   - プロジェクトが無料トライアル中、または請求先アカウントが停止・未設定だと、申請が却下されることがあります（Google 公式の記載）。Google Ads API 自体の利用料はかかりませんが、請求先アカウントのつながったプロジェクトが必要な場合があります。

### 4. 広告アカウントの ID を控える

Google 広告の画面右上に出る `123-456-7890` の形の番号（お客様 ID）。ハイフンを除いた10桁を、あとで Vercel の環境変数 `GOOGLE_ADS_CUSTOMER_ID` に入れます。管理者アカウント（MCC）経由で見ている場合は、その管理者アカウントの ID も控えます。

## 終わったら

「Google 広告の準備が終わった」とトレンド・SEO部署に伝えてください。こちらで、アプリの改修（Codex）と動作確認をしてから、定期実行を追加します。Vercel への環境変数の設定は、改修のあとにお願いします（どの名前に入れるかはそのときにお伝えします）。

参考: [サービスアカウントでの接続（Google 公式）](https://developers.google.com/google-ads/api/docs/oauth/service-accounts)

## アプリ側の改修（2026-11-07 実装済み・未接続）

- 認証は、GA4・Search Console と同じサービスアカウント（共通の認証処理に広告用スコープ `https://www.googleapis.com/auth/adwords` を渡す）に統一。リフレッシュトークン方式と Developer Token は使わない。
- 必要な環境変数: 既存の `GOOGLE_SERVICE_ACCOUNT_EMAIL`・`GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY`（または `GOOGLE_SERVICE_ACCOUNT_JSON`）、新しく `GOOGLE_ADS_CUSTOMER_ID`（MCC 経由なら `GOOGLE_ADS_LOGIN_CUSTOMER_ID` も）。
- 定期実行: 毎月5日（日本時間10時台）に前月1日〜末日の「キャンペーン」レポートだけを取得。CRON_SECRET で守った専用の入口を追加し、画面からの手動取得はログイン必須のまま残した。本番反映・接続は未確認。
- 重複・失敗: 「広告アカウント・種類・期間」で同じ取り込みを見分け、同じ内容なら保存しない。数字が変わっていれば新しい版として保存し、成功した最新版だけを表示に使う。失敗した取り込みは成功扱いにしない。
- 同時保存を防ぐため既存テーブルにロック用の記録を置く。処理が強制終了してロックが残った場合は安全のため自動解除しない。復旧時は、以前の処理が完全に停止したことを確認し、別途ユーザーの承認を得たうえで、対象の `file_hash` が `google-ads-import-lock-v1` のロック行だけを確認し、`status` を `failed`、`memo` を空に戻す。実際の取り込み行は変更しない。
